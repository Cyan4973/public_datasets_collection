# Zenodo automotive CAN payload bytes (`uint8`)

- **Dataset ID:** `zenodo_automotive_can_payload_u8`
- **Date attempted:** 2026-08-18
- **Status:** blocked
- **Intended source:** permissively licensed Zenodo records containing real,
  normal-operation automotive CAN frame captures
- **Discovery log:**
  `.data/logs/zenodo_automotive_can_payload_u8/discover.latest.log`
- **Discovery evidence:**
  `.data/discovery/zenodo_automotive_can_payload_u8/summary.json`,
  `records.tsv`, `files.tsv`, and `probes.tsv`

## Intended value

The proposed family would add asynchronous in-vehicle telemetry and control
traffic to the 8-bit corpus. Frames would be grouped by capture and arbitration
ID, with each payload position emitted as a separate frame-order `uint8`
series. This preserves natural CAN message boundaries and avoids treating
container bytes or multi-byte decoded signals as native 8-bit measurements.

## Discovery performed

The license-first discovery searched six automotive-CAN query variants over
three Zenodo result pages each. After correcting an initial invalid page-size
request, the successful run inspected:

- 329 unique records;
- 26 records passing permissive-license and coarse real-capture filters;
- 137 bounded candidate files;
- 30 ZIP central directories and bounded prefixes from likely CSV members;
- four direct CSV prefixes.

The accepted license set was CC0 and CC BY. No candidate reached the required
raw-CAN schema evidence: an arbitration/message identifier together with
explicit payload bytes or a candump-style hexadecimal payload.

## Why it is blocked

The plausible licensed records exposed decoded or generated representations,
not raw CAN payload bytes:

- [Zenodo 820576](https://zenodo.org/records/820576), CC BY 4.0, is a genuine
  35-trip vehicle collection captured through an OBD2-connected BeagleBone.
  Its archive contains accelerometer, gyroscope, position, trip, and
  `obdData.csv` tables. The bounded `obdData.csv` prefix has five decoded
  database fields (for example `"1","3","04","0",<timestamp>`), not an
  arbitration ID plus byte payload. It may merit a separate per-PID OBD
  telemetry investigation, but it does not establish native `uint8` values.
- AUTOPILOT records such as
  [3601373](https://zenodo.org/records/3601373) and
  [3630454](https://zenodo.org/records/3630454), CC BY 4.0, contain decoded
  vehicle-dynamics columns and JSON-encoded CAM, DENM, positioning, event, and
  oneM2M messages. Incidental JSON keys named `id` and `payload` are not CAN
  frame evidence.
- [Zenodo 12807317](https://zenodo.org/records/12807317), CC BY 4.0, explicitly
  says its multivariate time series were decoded from raw logs so users would
  not need the original CAN data; the raw candump logs are not published.
- [Zenodo 15655963](https://zenodo.org/records/15655963), CC BY 4.0, is traffic
  generated by a CARLA/Autoware simulation rather than a real vehicle capture.

Promoting any of these as CAN payload bytes would misclassify decoded values,
serialized JSON text, or synthetic traffic as native 8-bit measurements.

## Retry condition

Do not repeat the broad Zenodo search. Retry only with an exact permissively
licensed real-vehicle source already known to expose raw CAN frames in an
inspectable format such as candump, ASC, BLF, PCAP, or a CSV containing an
arbitration ID and byte/hex-payload field. AEGIS 820576 should be evaluated
under a different dataset ID if its decoded per-PID value series are later
proven integral, naturally bounded to 8 bits, and sufficiently substantial.

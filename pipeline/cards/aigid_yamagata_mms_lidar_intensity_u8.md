- Risks: (1) Byte-level similarity to boreas_velodyne_alpha_prime_intensity_u8 is the main WEAK risk, though the scan geometry and point ordering differ. (2) The exact MMS hardware (vendor and model) is not documented in the README; the instrument line names only the program and system class. (3) Choosing 8-20 MB tiles favours partial edge tiles (coverage fringes), so the builder should say so. Alternatively pick by grid code and accept larger tiles (median zip 147 MB, so the 5 GB cap allows about 25 median tiles). (4) The /255 step must be shown lossless per point (verify recomputes it), or the judge may call it a remap. It is the exact inverse of the documented 8-to-16-bit storage scaling, the opposite of the hollow-width (widened codes) Harney-Silver rejection. (5) Long runs of similar road-surface codes (peak near 145-150) make the data low-entropy but not degenerate (254 distinct codes)

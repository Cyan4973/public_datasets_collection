# Zenodo Glacial-Isostatic Stress Fields Float64 — 2026-08-27

## Outcome

Accepted `zenodo_gia_stress_fields_f64`: six complete finite-element stress-
tensor component fields and one complete vertical-displacement field from a
time-dependent glacial-isostatic adjustment model.

Each sample is shaped `[time=161, depth=4, y=120, x=120]` and contains
9,273,600 native float64 values (74,188,800 bytes). The seven samples total
64,915,200 values and 519,321,600 primary bytes.

## New domain and shape

This family adds geodynamic finite-element solution fields. The committed
corpus contains measured PIV water-velocity fields and various regular image or
voxel grids, but no accepted stress tensor or finite-element displacement
history. Each source array combines a 161-step model history, four shallow-
Earth depth layers, and a 120x120 horizontal grid.

The six independent components S11, S12, S13, S22, S23, and S33 preserve the
symmetric stress tensor as separate natural source arrays. U3 preserves the
vertical-displacement solution. Their spatially smooth regions, symmetry,
fixed-boundary zeros, load evolution, and localized stress gradients provide a
distinct compression structure.

## Source, rights, and representation

Zenodo record `5266382`, published by Rebekka Steffen and Holger Steffen,
explicitly declares CC BY 4.0. The exact 79,464,343-byte archive and exact API
metadata response are identity-pinned.

The archive README documents an ABAQUS finite-element model under a simple
circular ice load. Results span 0–160 ka in 1 ka steps, depths of 2.5, 7.5,
12.5, and 17.5 km, and horizontal coordinates from -2975 to 2975 km at 50 km
spacing. Stress is stored in MPa and displacement in metres.

All seven NetCDF4 members use an HDF5 version-2 object header, rank-4
`[161,4,120,120]` dataspace, exact `H5T_IEEE_F64LE` datatype descriptor, and a
contiguous 74,188,800-byte result payload. The recipe copies these little-
endian words unchanged; no narrowing, scaling, interpolation, or HDF5 library
is involved.

## Verification

Verification pins archive, metadata, member, and payload identities; validates
the exact ZIP member set and embedded README; parses the relevant HDF5 object
messages; checks the datatype, shape, layout, internal dataset names, payload
extent, finite ranges, zero counts, and byte-distinct outputs; and compares all
generated bytes against a fresh source extraction. All seven fields are finite
and nonconstant.

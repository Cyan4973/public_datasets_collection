# mdCATH All-Atom Protein Molecular-Dynamics Per-Atom Force Trajectories (CHARMM22*/ACEMD, kcal/mol/Å), Native Float32

- Candidate id: `mdcath_protein_md_atomic_forces_f32`
- Width: float32
- Quantity: Per-atom Cartesian force vectors (kcal/mol/Angstrom) on every protein atom at every saved frame of a classical all-atom explicit-solvent MD trajectory of a CATH domain (ACEMD engine, CHARMM22* force field). Primary field is the replica group's 'forces' dataset, shape (numFrames≈430-450, numProteinAtoms, 3). Proposed slice: one fixed temperature (348 K) and replica 0 per domain.

The repo's h5lite.py already covers all of this except layout v4, which needs a few lines: superblock v3 at 0, then root OHDR v2 at 0x30, then dense links (FRHP fractal heap plus v2 B-tree) to the /<domain> group, then '348', then '0', then the 'forces' OHDR. Read the Dataspace (frames, atoms, 3), the Datatype (class 1, size 4, LE IEEE float) and a Data Layout message v4 class 1 giving the contiguous (address, size). There is no Filter Pipeline message. download.sh then does curl -L -r addr-(addr+size-1) on the pinned resolve URL (xet CDN, returns 206), and the raw bytes are the LE float32 sample. Check size == frames*atoms*3*4 and that frames matches the replica attr numFrames. In probes the metadata walk took about 1.5 MB (23 x 64 KB ranges) per file.

- Homogeneity: One quantity (per-atom force, kcal/mol/Å), one engine and force field (ACEMD, CHARMM22*, protein atoms only, solvent filtered out), and one fixed temperature (348 K, replica 0) across all domains. Mixing the five temperatures would change the force-magnitude distribution, so they are deliberately excluded. Domains are picked deterministically (every 135th of the 5,398 sorted domain IDs), so they span CATH classes and sizes (639 to 2,000+ atoms). The (frame, atom, xyz) interleave is the native array layout. Coordinates in the same files must NOT be added (same-source column slice). Note that the first coords frame looked quantized to 0.01 Å, whereas forces are full-entropy.
- Risks: Range-based HDF5 navigation (superblock v3, v2 object headers, fractal heap, v2 B-trees, layout message v4) is more involved than a plain download. The builder can pin per-file (address, size) in a discovery step and re-validate in download.sh. Full files are 196 MB-2.5 GB, so whole-file download would be wasteful and must be avoided. HF resolve redirects to the xet CDN, so the revision must be pinned. Force distributions are heavy-tailed (±80+ kcal/mol/Å seen in one 4 KB probe). Sample sizes vary with domain size, but that is natural.

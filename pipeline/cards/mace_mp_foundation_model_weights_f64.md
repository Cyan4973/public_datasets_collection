- Decode path: Each .model file is a STORED (method 0) torch zip with <prefix>/data.pkl (188-250 KB), <prefix>/data/<key> raw little-endian storages and a version file; it uses data descriptors, so read sizes from the central directory. Use zipfile plus a pickle.Unpickler subclass whose find_class returns inert stubs for all mace/e3nn/torch.nn/torch.fx classes. It allows only builtins.set, collections.OrderedDict and _codecs.encode, and maps torch._utils._rebuild_tensor_v2 and _rebuild_parameter to recorders of (storage key, offset, size, stride). persistent_load returns ('storage', DoubleStorage, key, location, numel). Walk the module tree's _parameters OrderedDicts to get names. Select F64 Parameters with numel >= 1000 and slice storage bytes with struct '<d'. Exclude buffers (e.g. symmetric-contraction U matrices, atomic energies) and LongStorage. data.pkl globals were verified via pickletools: ScaleShiftMACE, e3nn Linear/TensorProduct/FullyConnectedNet, torch.fx reduce_graph_module, _rebuild_parameter, DoubleStorage, LongStorage.
- Novelty kind: downstream_mirror_fill
- Novelty evidence: novelty.py: no URL or term matches for mace/interatomic. No registry or ledger rows. There are no local 64-bit ML-weight recipes; local weight families are only at 16/32 bits (smolLM2 f16, timm resnet18 f32, GenCast f32). Downstream le-u64 has nn_weight_f64 (DINO/GPT-2 tensors, which appear to be float32 widened). This candidate fills that 64-bit gap with natively float64-trained weights.
- Homogeneity: One architecture family (ScaleShiftMACE, same codebase), one training-data family (MPtrj or MPtrj+sAlex), all trained float64 parameters in one unit-free weight regime. Suggested bounded set: one checkpoint per generation (0a small/medium/large, 0b3 medium, MPA-0 medium), about 299 MB download. 0b and 0b2 may be added if more volume is wanted, but they are close relatives.
- Risks: The pickle stub-unpickler is the main build risk: e3nn/fx GraphModule state must load inertly, and the builder must never import torch or execute pickle code beyond whitelisted stubs. Parameter-vs-buffer separation must be done carefully; one 46.7 MB storage in 0b3/MPA-0 could be a large buffer rather than a weight, so check it is a Parameter. Successive generations may be partially fine-tuned from each other (correlated tensors). Skip MACE_MPtrj_2022.9.model and the L0 epoch-199 duplicate, which are not in the README table.
- Probe evidence: GitHub releases API listed assets and sizes; README license rows quoted. Range GETs (github.com release redirect accepts explicit -r a-b) read the zip central directories: L0 small has 71 members, 69 storages, 32.38 MB; 0b3-medium and MPA-0-medium have 93 members, 89 storages, 79.2 MB each. Decoded storage samples: L0 data/12 has 16,384 doubles in range -6.44..6.11 with f32-exact fraction 0.0. 0b3 data/75 and data/36 and MPA-0 data/75 and data/36 all have f32-exact fraction 0.0, so the weights are genuinely float64-trained, not upcast. The 2024-01-07-mace-128-L2.sh training script has no --default_dtype override (MACE default float64).

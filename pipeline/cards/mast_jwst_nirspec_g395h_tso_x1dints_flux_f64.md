# JWST NIRSpec Bright-Object Time-Series (F290LP/G395H, NRS1) Level-2 Per-Integration Extracted 1-D Spectra: x1dints EXTRACT1D FLUX (Jy) Native Float64

- Candidate id: `mast_jwst_nirspec_g395h_tso_x1dints_flux_f64`
- Width: float64
- Quantity: Spectral flux density in Jy of the target star, extracted by the JWST calwebb pipeline (extract_1d) for every integration of a NIRSpec BOTS exoplanet-transit or eclipse time series. One row per integration, one 1-D spectrum per row, about 1272-2048 wavelength bins over 2.87-3.72 um on NRS1. NaN edge bins are kept as the native fill (about 2.5% per row).

Caom.Products lists *_seg001_nrs1_x1dints.fits for each. Pin names and sizes in sources.tsv. download.sh range-GETs the FITS headers (first ~80 KB), then fetches only the FLUX slices with HTTP multi-range requests: MAST answers 'Range: a-b,c-d,...' with 206 multipart/byteranges (verified). Each row is INT_NUM(J) + WAVELENGTH(nD) + FLUX(nD) + ..., so FLUX sits at byte offset 4+8n in every NAXIS1-byte row, and the download stays close to the primary bytes. Whole-file fallback is 70-365 MB per segment. Python stdlib: parse the 80-char FITS cards (EXTNAME='EXTRACT1D', TFORMn='1272D', NAXIS1/NAXIS2), split the multipart body by boundary, and struct-unpack '>%dd' to little-endian float64. Verified on jw01366003001_04101_00001-seg001_nrs1: data starts at byte 46080, wavelength 2.8617-3.7210 um, 1240/1272 finite flux values in row 1, 1240 distinct, none float32-exact.

- Novelty evidence: novelty.py --url mast...Download/file --terms x1dints nirspec matches only nasa_tess_lightcurves_f32 (same MAST download endpoint, different mission and product), with no registry, ledger or downstream term hits. The spectrum_1d type exists only at 32 bits (DESI coadd flux, ICRAF MIR, marine DOM MS1, powder XRD), and there is no 64-bit spectral-flux family. The only JWST recipe is mast_jwst_nircam_sw_uncal_ramps_u16 (raw u16 imaging ramps, a different product and quantity). TSIS SIM SSI (screened out) was a single 85 MB file of 9-digit-rounded near-identical solar spectra. This material is native pipeline float64 with photon noise, from 60 independent stars and visits.
- Homogeneity: One instrument mode only: NIRSpec fixed slit S1600A1, BOTS, F290LP/G395H, detector NRS1, seg001, preferably subarray SUB2048, so the wavelength grid, unit (Jy), pipeline step and noise process are shared. Exclude NRS2, PRISM, G140H/G235H, NIRISS SOSS and MIRI (different grids and regimes). Target brightness varies (roughly 1e-3 to 1e-1 Jy), which is an exponent shift of the same quantity, not a different tick lattice. Keep FLUX only: no FLUX_ERROR, variances or SURF_BRIGHT.
- Risks: (1) Byte-gate: consecutive integrations are near-identical apart from photon noise, so a judge could raise the 'near-duplicate fixed-length series' objection (TSIS precedent). The mitigation is genuine unrounded float64 noise (relative scatter about 1e-3, not 1e-4 with rounding) across 60 visits of different stars. zlsim could still find it equivalent to an existing smooth f64 family. (2) Edge NaNs (about 2.5%) must be declared native fill and verified. (3) Some programs may be reprocessed with new pipeline versions, so pin sizes and the CAL_VER header and tolerate drift by name re-discovery. (4) The builder must parse multipart/byteranges correctly and batch about 200 ranges per request, since MAST rate-limits.

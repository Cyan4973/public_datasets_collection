# Fermi GBM Burst Time-Tagged-Event (TTE) NaI Photon Arrival Times Float64

- Candidate id: `fermi_gbm_tte_nai_photon_arrival_times_f64`
- Width: float64
- Quantity: Arrival times of individual gamma-ray photon events (seconds relative to the burst trigger time, about 2 µs instrument resolution) recorded by a Fermi Gamma-ray Burst Monitor NaI(Tl) detector. This is the native `1D` TIME column of the EVENTS binary table in each burst TTE file. Primary series: TIME only. PHA, EBOUNDS, GTI and the TZERO/TRIGTIME header values are auxiliary or not emitted.
- Source: https://heasarc.gsfc.nasa.gov/FTP/fermi/data/gbm/bursts/
- Resources: https://nasa-heasarc.s3.amazonaws.com/?list-type=2&prefix=fermi/data/gbm/bursts/, https://nasa-heasarc.s3.amazonaws.com/fermi/data/gbm/bursts/2020/bn200101861/current/glg_tte_n0_bn200101861_v00.fit, https://heasarc.gsfc.nasa.gov/FTP/fermi/data/gbm/bursts/2009/bn090606471/current/, https://fermi.gsfc.nasa.gov/ssc/data/policy/
- License: NASA SMD Open Scientific Data Policy (LicenseRef-NASA-SMD-Open-Data). This is the same basis as the accepted HEASARC recipes nasa_heasarc_batse_cont_counts_i16 and nasa_heasarc_nicer_pi_i16.

- Natural record: One complete burst TTE file for one NaI detector, i.e. the whole EVENTS.TIME column of glg_tte_nX_bnYYMMDDFFF_vNN.fit. Observed sizes run from about 340k events (2009, 3.4 MB file) to about 717k events (2020, 7.2 MB file). Proposal: about 100 bursts evenly spaced over the 4,392 burst directories from 2008 to 2026, highest version in current/, one NaI file per burst. Either use a fixed detector (n0), or pick the largest NaI TTE file in the pinned listing, which is the detector carrying the burst signal. BGO files are excluded to keep one detector regime.
- Estimated samples: 100
- Estimated primary values: 60,000,000
- Estimated download bytes: 620,000,000
- Estimated primary bytes: 480,000,000
- Decode path: curl the uncompressed FITS from the anonymous nasa-heasarc S3 mirror (S3 ListObjectsV2 gives sizes and ETags for pinning). Pure-stdlib FITS walk: read 80-char header cards in 2880-byte blocks to reach the EVENTS BINTABLE (NAXIS1=10, TFORM1='1D' TIME, TFORM2='1I' PHA). Unpack rows with struct '>dh' and write TIME as little-endian float64. Emit the stored D values (seconds since TZERO=TRIGTIME) as the native field, and record TZERO in metadata. Applying TZERO in float64 for absolute MET is also possible. Validate that NAXIS2 × 10 equals the table size and that times are non-decreasing.
- Novelty kind: new_quantity
- Novelty evidence: novelty.py --url .../fermi/data/gbm/bursts/ --terms fermi gbm tte photon: no recipe, registry, ledger or downstream match. Host-only overlap with the NICER/SDO/BATSE HEASARC recipes, which use different missions and files. The local corpus has no gamma-ray event data at any width. The only event time-tag family at 64 bits is dc_lidar_2015_gps_time_f64 (aerial LiDAR), which is a different instrument and modality. No 64-bit family in this effort comes from high-energy astrophysics instruments.
- Homogeneity: Single instrument (GBM NaI(Tl)), a single quantity (photon arrival time in seconds relative to trigger), one 2 µs clock lattice, and the same FITS layout from 2008 to 2026. Events are time-sorted (checked on 864 decoded rows, min dt about 3.9 µs). Burst-window lengths and count rates vary by epoch and burst brightness. That is natural content variation, not a regime mix. BGO detectors and CTIME/CSPEC binned products are excluded.
- Risks: A judge may argue that event TIME is a timestamp, i.e. auxiliary. Counter: in TTE data the arrival time is the primary measurement, and dc_lidar_2015_gps_time_f64 is accepted precedent. The builder must document stored-vs-TZERO semantics. A few bursts lack TTE or have v01 replacements, so the recipe should resolve the highest version from the listing and skip bursts without TTE. Early-mission TTE files (2008-2012) cover shorter windows. The PHA column (128 channels) must not be emitted as a 64-bit series.
- Probe evidence: The HEASARC directory listings are live. Burst counts: 2008=124, 2009=250, 2013=232, 2024=228, 2025=271, 2026=214, total 4,392. Each burst has 12 NaI + 2 BGO TTE files. The S3 mirror ListObjectsV2 returned glg_tte_n0_bn200101861_v00.fit Size=7200000 with an ETag. A one-byte range GET with -L returned 206. A 28.8 KB header range read gave: EVENTS BINTABLE NAXIS1=10, NAXIS2=716914, TFORM1='1D' TTYPE1='TIME' TUNIT1='s' TZERO1=599603971.451430, TFORM2='1I' PHA. The first decoded rows were (-135.170529961586, 15), (-135.16963386535645, 62), ...; sorted, min dt 3.93e-6 s. A 3 MB range transfer from S3 ran at about 2.1 MB/s.

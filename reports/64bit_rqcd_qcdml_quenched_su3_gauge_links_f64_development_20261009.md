# RQCD qcdML quenched SU(3) gauge-link float64 development

## Outcome

Accepted `rqcd_qcdml_quenched_su3_gauge_links_f64`. It holds 100 gauge configurations from one quenched lattice-QCD Markov chain in the RQCD collaboration's qcdML project (ensemble `ldg/rqcd/qcdML/ens_001`).

This is the corpus's first lattice gauge field material at any width, locally or downstream. Each sample is a 4-D periodic lattice of 3×3 special-unitary matrices, generated by Markov-chain Monte Carlo. Individual entries look Haar-random. The structure lies in the exact algebraic constraints (unitarity, det 1, row 3 = conj(row1 × row2)) and in weak lattice-local correlations (mean plaquette ≈ 0.594).

The measured breadth is `OK`. The nearest family is `figshare_rmd17_trajectories_f64`: feature distance 0.0464 but compression loss 0.094, so the two are not compression-equivalent.

## Source and rights

- Source: Zenodo record 15018324, "ldg/rqcd/qcdML/ens_001" (D. Knüttel, University of Regensburg), published 2025-03-13. The record describes itself as "A quenched QCD ensemble for machine learning projects".
- Physics: plaquette gluon action at β=6.0 on an 8×8×8×16 lattice, generated by SU(2) heat bath (niter 20, project_method "defect"). The chain has 5,000 configurations, `config_0.pt` .. `config_4999.pt`.
- File: `ens_001_pt.zip`, 22,571,455,882 bytes, md5 `58d0a6911c07480ff914417d4498d8bc` (Zip64, 5,002 entries).
- License: CC BY 4.0. Live record metadata shows `license.id = cc-by-4.0` and `access_right = open`. The license applies to the single file in the record. `download.sh` re-checks the license, title, physics parameters, size and md5 on every run.

## Shape and conversion

- The archive is never downloaded whole. `download.sh` range-fetches the last 1 MiB and parses the Zip64 EOCD locator, the Zip64 EOCD and the 522,652-byte central directory with `struct`. It confirms that configs 0..4999 exist.
- It then range-fetches 100 pinned members, configs n = 300 + 47k for k = 0..99. Each member's offset, compressed size, uncompressed size and CRC32 is pinned in `scripts/selected_members.tsv`.
- Each member is raw-inflated with its CRC32 checked. The inner torch `.pt` is a stored zip.
  - `byteorder` must be `little` and `version` must be 3.
  - `data.pkl` is checked with `pickletools.genops` only and never unpickled: `ComplexDoubleStorage`, numel 294,912, storage offset 0, shape (4,8,8,8,16,3,3), contiguous stride, and a pinned SHA-256.
  - `data/0` (4,718,592 bytes) is written unchanged. torch complex128 LE is bit-identical to interleaved (re, im) LE float64.
- One sample per configuration. The axes are (mu, x, y, z, t, row, col, re_im).
- Configs before 300 are skipped because the chain starts out of equilibrium (plaquette 0.695 at config 0). The 47-config spacing limits autocorrelation.
- The sibling ensemble ens_004 (16^3×32, HMC) is excluded so that lattice volume and algorithm are not mixed.

# CGRO BATSE CONT Daily 16-Channel Large-Area-Detector Gamma-Ray Count Spectra Int16

- Candidate id: `nasa_heasarc_batse_cont_counts_i16`
- Width: int16
- Quantity: Raw photon counts accumulated per 2.048 s in each of 16 energy channels (about 20 keV to 2 MeV) for each of the 8 BATSE Large Area Detectors (NaI(Tl) scintillators) on the Compton Gamma Ray Observatory. Source column: FITS BATSE_CNTS.COUNTS, TFORM '128I', TDIM '(8,16)' (detector axis fastest), TUNIT COUNTS, no TZERO/TSCAL/TNULL.
- Source: https://nasa-heasarc.s3.amazonaws.com/compton/data/batse/daily/
- Resources: https://nasa-heasarc.s3.amazonaws.com/compton/data/batse/daily/09001_10000/09401_09500/dds09401/cont_09401.fits.gz, https://nasa-heasarc.s3.amazonaws.com/compton/data/batse/daily/08001_09000/08361_08400/dds08371/cont_08371.fits.gz, https://nasa-heasarc.s3.amazonaws.com/compton/data/batse/daily/10001_11000/10001_10100/dds10064/cont_10064.fits.gz, https://nasa-heasarc.s3.amazonaws.com/compton/data/batse/daily/11001_12000/11601_11700/dds11672/cont_11672.fits.gz, https://nasa-heasarc.s3.amazonaws.com/compton/data/batse/daily/README

- Natural record: One BATSE CONT daily FITS file (cont_<TJD>.fits.gz): the whole BATSE_CNTS.COUNTS column over all rows of that day, stored as rows × 16 channels × 8 detectors in native row order. A row is one 2.048 s accumulation; a full day has about 28,000 to 37,000 rows, i.e. about 3.6 to 4.7M values. The file is the archive's natural daily product. Do not tile or merge days.

- Decode path: curl the pinned .fits.gz files from the S3 mirror (resumable, stall-based). In Python, open with gzip. Walk the FITS 2880-byte header blocks to HDU 2 (EXTNAME 'BATSE_CNTS'), then assert NAXIS1=336, TTYPE7='COUNTS', TFORM7='128I', TDIM7='(8,16)' and no TZERO7/TSCAL7. For each row, read the 256 bytes at row offset 28 (MID_TIME D, then five E fields: X/Y/Z_POS, GEO_AZ, GEO_EL) with struct '>128h', and write little-endian int16 (array('h') + byteswap). Pure stdlib only: gzip, struct, array.

- Homogeneity: Every value has the same meaning and unit: LAD counts per 2.048 s per energy channel, from 8 identical NaI(Tl) Large Area Detectors with one telemetry format. I checked the schema on TJD 08371 (1991), 10064 and 11672 (2000): 336-byte rows, COUNTS 128I (8,16) in all three. Keep only CONT. Exclude DISCLA (it mixes the 4 discriminator channels with total and charged-particle-detector counts), HER/SHER (different resolution and detectors) and trigger/burst products. Recommend a deterministic spread over the 1991–2000 mission, e.g. ~40 days evenly spaced in TJD, or the first near-full day of each quarter (file >6 MB; 2,947 of 3,318 days qualify).
- Risks: (1) Rare telemetry glitches: TJD 10000 had 2 negative values (-29324) and about 14 values above 4096 out of 3.8M. Keep them as native int16 and document; there is no null sentinel. (2) Partial days (smallest files 0.3 MB) should be skipped with a size or row floor, not padded. (3) Counts sit mostly in 7–11 bits (64–2047), which uses the 16-bit width honestly, but the top bits are rarely set. (4) heasarc.gsfc.nasa.gov and the NASA policy page are currently proxy-blocked: download from the nasa-heasarc S3 mirror and rely on the license evidence already in the NICER recipe. (5) Directory placement is irregular (cont_10000 lives under 10001_10100/), so discover paths from the S3 listing and pin exact keys, sizes and sha256.
- Probe evidence: Paginated S3 listing of compton/data/batse/daily/ found 3,318 cont_*.fits.gz files, TJD 08362–11690 (1991-04 to 2000-05), 24.9 GB total, 0.30–9.85 MB each. One-range GETs on cont_09401, 08371, 10064 and 11672 all returned HTTP 206, and their decoded headers show the same CONT schema.
